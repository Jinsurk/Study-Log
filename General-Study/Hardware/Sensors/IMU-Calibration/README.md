# Nano 33 IoT IMU 보정 실습

2026-10-07~08, Windows 노트북과 Arduino Nano 33 IoT의 내장 IMU로 수행한 실험 기록이다. 자이로의 정지 바이어스를 측정하고, 가속도계를 6면 방식과 20개 정지 자세의 타원체 모델로 보정했다. 보정에 사용하지 않은 새 자세 3개에서는 다중 자세 보정의 가속도 크기 오차가 두 다른 방식보다 작았다.

이번 결과는 정지 상태의 가속도 크기와 자이로 영점에 관한 것이다. 자이로 스케일·축 정렬·온도 보정, 동적 자세 추정, IMU–LiDAR 외부 보정은 아직 수행하지 않았다. 보정 행렬을 Nano에서 실시간 적용하는 작업도 후속 단계다.

## 파일 구성

| 경로 | 내용 |
|---|---|
| [arduino/](arduino/) | 실제 업로드해 사용한 C++ 스케치 |
| [scripts/](scripts/) | PowerShell 수집, Python 계산·검증 프로그램 |
| [data/](data/) | 완전한 원본 CSV. 선택된 20개 자세와 과거 6면·검증 데이터 |
| [results/](results/) | 계수, 행렬, 선택 근거, 파생 CSV와 검증 당시 모델 스냅샷 |

실패한 `.partial.csv`와 제외·삭제한 중복 자세는 포함하지 않았다. 과거 6면 재측정 기록은 실험 경과와 재계산을 위해 보존했다. `multi_pose_selection.json`에 적힌 파일만 20개 자세 피팅에 사용한다.

## 환경과 데이터의 의미

- 보드: Arduino Nano 33 IoT, `Arduino_LSM6DS3` 라이브러리로 데이터 취득 성공.
- 컴퓨터: Windows, Windows PowerShell, Python 3.12와 NumPy. 정확한 Arduino 코어·라이브러리 버전, 센서 온도, IMU 레지스터 설정은 별도 기록하지 않았다.
- 통신: USB `Serial`, 프로그램 설정 115200. 실습 당시 COM3 사용. COM 번호는 실행 환경에서 다시 확인한다.
- 가속도계 단위: g. 자이로 단위: °/s.
- `t_us`: MCU가 데이터 준비를 확인한 뒤 읽기 직전에 기록한 경과 시간. 센서 내부 샘플 생성 시각이나 PC 시각은 아니다.
- 각 수집은 PC의 `S` 명령 → 5초 대기 → 새 데이터 1,000개 → `DONE` 순서다. `loop()`에서 추가 측정하지 않는다. 재수집 전 RESET을 누른다.
- 가속도 수집은 USB 출력 안정성을 위해 행 단위 전송과 20 ms 대기를 적용했다. 약 104 Hz 센서 설정과 실제 CSV 저장 빈도는 구분해야 한다.

## 1 자이로 바이어스

보드를 정지시킨 채 각속도 1,000개를 수집했다. 처음 시리얼 모니터에서 읽은 바이어스는 `(-0.00812, -0.49616, +0.07280)` °/s였다. 이후 CSV에 저장한 별도 수집의 평균을 실제 검증에 사용했다.

```text
bias = mean(stationary raw gyro)
corrected gyro = raw gyro - bias
```

| 축 | CSV 바이어스 (°/s) | 수집 표준편차 (°/s) | 새 검증 원본 평균 | 새 검증 보정 평균 |
|---|---:|---:|---:|---:|
| X | -0.00721000 | 0.02174370 | -0.01260000 | -0.00539000 |
| Y | -0.50085000 | 0.02792413 | -0.49917000 | +0.00168000 |
| Z | +0.07413000 | 0.02578193 | +0.07840000 | +0.00427000 |

보정용 데이터: [gyro_20261007_135515_052.csv](data/gyro_20261007_135515_052.csv). 검증: [gyro_validation_20261007_135816_859.csv](data/gyro_validation_20261007_135816_859.csv).

검증 CSV의 보드 출력 보정값 3개가 원본에서 계산한 값과 일치하지 않았다. PC에서 원본을 다시 계산한 [요약](results/gyro_validation_20261007_135816_859.recomputed.summary.csv)을 표에 사용했다. 불일치 원인은 확정하지 않았다. 원본 보정용 수집에도 366번째 Z 값 `0.70000` °/s가 한 번 있었으며 삭제하지 않았다.

일정한 바이어스를 빼면 평균은 이동하지만 표준편차는 변하지 않는다. 이 실험은 자이로 전체 교정이 아닌 정지 바이어스 보정이다.

## 2 가속도계 6면 보정

정지 상태에서 가속도 벡터의 크기를 약 1 g로 가정한다. 각 축을 중력 방향과 반대 방향으로 놓아 ±축 평균을 구한다.

```text
offset = (positive_mean + negative_mean) / 2
raw_scale = (positive_mean - negative_mean) / 2
gain = 1 / raw_scale
corrected_axis = (raw_axis - offset) * gain
```

실제 측정으로 USB 포트 위가 +X, 아래가 -X임을 확인했다. 부품 면 위는 +Z, 아래는 -Z였다. 긴 옆면을 아래로 놓으면 ±Y가 잡혔고, 어느 부호인지 실제 측정으로 확인했다. 재수집에서 `pos5`는 -Y, `pos6`는 +Y였으므로 파일 번호로 부호를 고정하지 않았다.

수집 당시 받침으로 정렬한 자세에는 기울기 영향이 남을 수 있다. 위 식은 정확히 ±1 g가 해당 축에 걸린다는 가정이므로 기울기와 축 사이 결합을 따로 추정하지 못한다.

| 축 | 최종 6면 오프셋 (g) | 보정 배율 |
|---|---:|---:|
| X | -0.0116560560 | 0.9978753906 |
| Y | -0.0168447525 | 0.9991719408 |
| Z | +0.0260576195 | 0.9924449094 |

[최종 6면 모델](results/accel_calibration.json)에 사용한 파일 목록을 기록했다. [최초 6면 모델](results/accel_calibration_initial.json)도 보존했다. 최초 검증의 tilt3에는 약 0.6% 잔여 크기 오차가 반복돼 6면 데이터를 다시 수집했다. 재수집 모델은 이전 검증 자세 일부에서는 좋아지고 일부에서는 나빠졌다. 재측정만으로 모든 방향의 정확도가 개선됐다고 판단하지 않았다.

## 3 20개 정지 자세 보정

정확한 각도를 알 필요 없이 +Z/-Z, ±X/±Y 중심 방향과 세 축에 중력이 나뉘는 방향으로 보드를 고정했다. 자세 사이의 움직임은 기록하지 않았고, 각 정지 자세에서 원본 1,000개를 모았다. 총 20,000개이며 각 자세의 평균 하나에 같은 가중치를 주어 피팅했다.

중복 측정은 완전성, 축별 흔들림, 앞·뒤 절반 평균 차이와 튄 값을 비교했다.

| 자세 | 선택한 파일 시각 | 근거 |
|---|---|---|
| pose13 | 12:24:10 | 전체 축 흔들림이 작은 재측정. 6σ 기준 튄 값 하나는 남아 있으며 행 삭제하지 않음 |
| pose15 | 12:30:42 | 사용자가 지정한 재측정이며 흔들림·튀는 값도 적음 |
| pose16 | 12:34:31 | 나중 재측정보다 흔들림과 튄 값이 적음 |

[선택 기록](results/multi_pose_selection.json)과 [모델 manifest](results/accel_multi_calibration.json)가 실제 파일 선택의 기준이다. 제외한 중복 원본 3개와 요약 3개는 사용자의 요청으로 로컬에서 삭제했다. 선택되지 않은 기록의 품질 수치는 선택 기록에 남겼다.

모델은 다음과 같다.

```text
corrected_g = C * (raw_g - offset_g)
```

일반 타원체를 선형 최소제곱으로 추정하고, 양의 정부호 행렬의 Cholesky 분해로 위삼각 보정 행렬 C를 만든다. 비대각 성분은 정지 크기 오차의 축 사이 결합을 보정한다. 중력 크기만으로 절대 회전은 결정되지 않으므로 이 C를 실제 센서 축의 절대 회전 행렬로 해석하지 않는다.

```text
offset_g = [-0.0100256141, -0.0146572613, +0.0256654756]

C = [ 0.9965129979  -0.0003058205  -0.0087262995 ]
    [ 0             0.9983658358   0.0014641727 ]
    [ 0             0             0.9913144365 ]
```

설계행렬은 rank 9, 조건수 약 6.47로 계산됐다. 학습 자세 평균의 크기 RMSE는 0.000517 g다. 자세 하나를 빼고 피팅해 그 자세를 예측하는 leave-one-pose-out RMSE는 0.001165 g다. 학습 오차만으로 성능을 판단하지 않고 아래 새 측정으로 비교했다.

이번 구현은 [Tedaldi et al., ICRA 2014](https://albertopretto.altervista.org/papers/tpm_icra2014.pdf)의 다중 자세 아이디어와 연결되는 가속도계 정적 크기 보정 실습이다. 논문의 정지 검출, 자세 사이 회전 적분, 자이로 스케일 보정 전체를 재현한 것은 아니다.

## 4 새로운 세 자세에서 검증

2026-10-08, 모델을 고정한 뒤 별도 자세 3개에서 1,000개씩 수집했다. raw, 최종 six_face, multi에 같은 원본을 적용했다. 검증 데이터로 모델을 다시 피팅하지 않았다.

```text
norm = sqrt(ax*ax + ay*ay + az*az)
RMSE = sqrt(mean((norm - 1)^2))
```

| 검증 자세 | 원본 RMSE (g) | 6면 RMSE (g) | 다중 자세 RMSE (g) | 다중 자세 평균 크기 (g) |
|---|---:|---:|---:|---:|
| tilt1, 14:04:56 | 0.028688539 | 0.004363586 | **0.001450215** | 1.001020140 |
| tilt2, 14:07:21 | 0.013429709 | 0.001796933 | **0.000917062** | 0.999918732 |
| tilt3, 14:08:57 | 0.000965372 | 0.001233847 | **0.000812010** | 0.999374210 |

다중 자세 보정의 RMSE는 6면 대비 각각 약 66.8%, 49.0%, 34.2% 작았다. tilt3 원본은 이미 1 g에 가까워 6면 보정이 오히려 악화됐지만 다중 자세 보정은 원본보다 약 15.9% 개선됐다.

판단 범위는 **이번 세 정지 자세의 가속도 크기**다. tilt1 X축 표준편차는 약 0.00266 g로 다른 기록보다 컸다. 모든 방향, 온도, 동적 가속도, 절대 자세 정확도를 보장하지 않는다. 전날 검증 데이터에서도 다중 자세 보정이 6면보다 항상 좋았던 것은 아니다.

검증 당시 모델과 결과는 각 CSV의 `.multi_models_used.json`, `.multi_summary.csv`에 저장했다. [전체 비교표](results/accel_multi_comparison.csv)에도 재계산 결과가 있다.

## 실행 방법

Arduino IDE에서 `Arduino_LSM6DS3` 라이브러리를 설치하고 [accel_capture.ino](arduino/accel_capture/accel_capture.ino)를 업로드한다. 시리얼 모니터와 플로터를 닫는다. PC의 Python에는 NumPy가 필요하다.

```powershell
python -m pip install -r .\scripts\requirements.txt

# 폴더를 현재 작업 디렉터리로 연 뒤, 각 자세에서 RESET하고 실행
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\capture_accel.ps1 -Port COM3 -Position pose01

# 포함된 20개 원본과 선택 기록으로 다중 자세 모델 재계산
python .\scripts\calibrate_multi.py

# 새 정지 자세에서 수집하고 두 모델 비교
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate_multi.ps1 -Port COM3 -Position tilt1
```

저장 경로는 현재 작업 디렉터리가 아니라 실습 폴더의 `data/`다. 새 수집의 파생 결과도 원본 옆에 저장되며, 포함된 과거 결과는 `results/`에 정리했다. `results/`의 모델 파일은 검증 프로그램이 읽는다. 경로 구조를 유지해 실행한다. ExecutionPolicy Bypass는 해당 프로세스에만 적용한다.

`calibrate_accel.py`는 각 pos 번호의 최신 완전한 파일에서 실제 부호를 판별해 6면 모델을 재계산한다. `calibrate_multi.py`는 명시적 선택 manifest를 우선한다. 새 데이터로 피팅하려면 선택 manifest를 의도적으로 갱신해야 한다. 모델 재계산은 해당 결과 파일을 덮어쓰므로 기존 모델과 검증 스냅샷을 구분한다.

자이로용 `imu_capture.ino`, `imu_validate.ino`와 저장 프로그램도 포함했다. 초기 보드 출력 보정값은 불일치가 관찰된 기록이므로 gyro 검증은 `analyze_validation.py`로 PC에서 다시 계산한다. 스케치는 당시 실제 사용 소스이며 저장소 정리 중 새 하드웨어 업로드를 수행하지 않았다.

## 오류와 해결 과정

- COM3 접근 거부: 시리얼 모니터·플로터 등 다른 프로그램이 포트를 점유할 수 있다. 종료 후 다시 열었다.
- 수집이 계속되는 것처럼 보임: 초기 코드의 `loop()`는 보정값을 계속 출력했다. 유한한 수집 스케치로 바꿔 1,000개 후 추가 측정하지 않도록 했다.
- CSV 두 행 결합: 724·725번 사이의 줄바꿈이 누락돼 엄격한 행 검증에서 중단됐다. 단일 행 문자열 전송, 부분 전송 재시도, flush, 가속도 수집 20 ms 간격으로 수정했다. 구체적인 누락 원인은 확정하지 않았다.
- 파일 이름과 실제 방향 불일치: pos5/pos6 Y 부호가 바뀌었다. 이름만으로 방향을 가정하지 않고 평균을 확인했다.
- 6면 보정 후 방향별 잔여 오차: 동일 자세에서 반복됨을 확인하고 다중 자세 피팅과 별도 검증으로 확장했다.
